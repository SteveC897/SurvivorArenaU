# 01 · 测试战斗场景

> 目的：先不接武器、成长、结算等系统，只跑通「5 分钟单局 + 30 波蝙蝠 + 主角移动 + 击杀光环 + 胜利」这条主战斗链路。
>
> 场景：`Assets/Scenes/MainGame.unity`　数据：`Assets/DataDocs/level01_enemy_spawn.csv`

---

## 一、运行方式

1. 用 **Unity 2022.3.62f3c1** 打开项目，打开 `Assets/Scenes/MainGame.unity`，直接 Play。
2. 操作：`WASD` / 方向键移动；胜利后按 `R` 重开。
3. 场景由代码生成，不手摆。如果场景引用丢了或想调参数后重建：
   `Tools → Survivor Arena → Rebuild Test Battle Scene`。
4. 打 Windows 测试包：`Tools → Survivor Arena → Build Windows Test Player`，
   输出到 `%TEMP%/SurvivorArenaTestBuild/SurvivorArenaU.exe`。

## 二、本场景的规则

| 项 | 规则 |
| --- | --- |
| 单局时长 | **5:00（300 秒）** |
| 波次 | **30 波，每 10 秒一波**，开波时间为 `0:00–4:50` |
| 敌人 | **只有蝙蝠**；从主角周围 12–14 单位外生成，直线向主角靠拢 |
| 刷怪 | 当前波次的「数量下限 + 补刷间隔」：存活数低于下限就按间隔补，达到下限就停 |
| 离屏回收 | 主角一直跑时，离主角超过约 16 单位（屏幕外）的存活蝙蝠会被移动到相机视野外的随机屏幕边缘；**不击杀、不消失、不重新生成**，只是改位置，击杀数不变 |
| 主角 | 可八向走动，**没有武器、没有攻击输入** |
| 测试攻击 | 以主角为圆心、**半径 2 单位（约 2 个身位）**的圆形判定区；敌人身体碰到即死 |
| 受击 | 主角不会受伤，本场景没有生命值/死亡流程 |
| 结束 | 时间到后停止刷怪、杀死场上全部敌人、弹出「胜利！」；`R` 重开 |
| 背包 | 左上角显示 **6 个武器槽 + 6 个被动槽**，全部为空 |

> 主角立绘本身拿着法杖（`player_imelda_*.png` 的生成素材如此），但本场景没有任何武器系统或装备数据；
> 左上角武器栏也是空的。后续接武器时再换立绘或加装备显示。

## 三、波次数据

`Assets/DataDocs/level01_enemy_spawn.csv` 由测试场景生成并直接读取。
数据取自 `Docs/吸血鬼幸存者-局内成长与节奏剖析.md` 第三节「疯狂森林完整波次表」：

- 源表 30 行，时间 `0:00–29:00`，对应本场景第 1–30 波；
- 只取源表的 **`下限`、`间隔(s)`** 两列；
- 源表 30 分钟压缩到本场景 5 分钟，比例 6:1；
- 敌人统一为蝙蝠；Boss/宝箱/地图事件等列本场景不使用；
- 源表 `30:00+` 的死神行不属于 30 波，未纳入。

因此，第 1 波用源表 `0:00` 行（15 / 1.0s），第 2 波用 `1:00` 行（30 / 1.0s）……
第 30 波用 `29:00` 行（300 / 0.1s），在局内 `4:50` 开波，`5:00` 收尾。

### CSV 列

| 列 | 含义 |
| --- | --- |
| `wave` | 波次序号 1–30 |
| `time_sec` | 本局开波时间（秒），0–290 |
| `time_label` | 本局时间 `mm:ss` |
| `enemy_id` | 敌人标识，本场景固定 `bat` |
| `enemy_name` | 显示名「蝙蝠」 |
| `minimum_count` | 场上存活数量下限 |
| `spawn_interval` | 补刷间隔（秒） |
| `source_minute` | 对应源表行时间，仅追溯用 |

> 备注：CSV 以 `#` 开头的行是注释，`WaveTable` 会跳过；字段不包含逗号/引号。

| 项 | 值 |
| --- | --- |
| 主角移速 | 4.2 单位/秒 |
| 光环半径 | 2.0 单位（主角 32px @ 32PPU = 1 单位） |

| 相机 | 正交，像素完美 32 PPU / 640×360；1080p 下 3 倍整数缩放 |

## 五、分层架构与代码结构

本次按 `JobHunt/Unity-技术实现清单.md` 的分层架构做了重构，目标不是增加玩法，而是把已有功能拆到正确的层，并用 asmdef 把依赖方向固定下来。

### 5.1 五层职责

| 层 | 职责 | 本项目的类 |
| --- | --- | --- |
| **Data** | 只读配置/表格 + 校验 | `WaveTable`、`WaveDefinition`、`BattleConfig`（ScriptableObject 资产） |
| **Core** | 与玩法无关的基础设施 | `GameClock`、`EventBus<T>`、`BattleEvents`、`ObjectPool<T>`、`IPlayerInput`、`IWorldViewport` |
| **Gameplay** | 规则、状态、系统 | `BattleSession`、`WaveScheduler`、`PlayerMotor`、`EnemySpawner`、`EnemyBat`、`KillAuraSystem`、`OffscreenRecycler`、`YSort` |
| **Platform** | 引擎/平台适配 | `LegacyPlayerInput`（旧 Input Manager） |
| **Presentation** | 场景表现 + HUD | `BattleHud`、`HudFont`、`PlayerSpriteView`、`AuraView`、`CameraFollow`、`CameraViewport`、`InfiniteGround` |
| **Bootstrap** | 组合根：唯一同时认识所有层的地方 | `BattleBootstrap` |

依赖方向（由 asmdef 强制）：

```
Data（无依赖）      Core（无依赖）
      ↑                  ↑
      └──── Gameplay ────┘
                ↑
          Presentation        Platform → Core
                ↑
            Bootstrap  → 以上全部
            Editor     → 以上全部（仅 Editor 平台）
```

- **Gameplay 不引用 Presentation**：击杀、刷怪、胜负只发 `EventBus` 事件。
- **Presentation 只订阅事件**：`BattleHud` 不持有 `BattleSession`/`EnemySpawner`，以后换 UI 方案不影响玩法。
- **Platform 只实现 Core 接口**：`PlayerMotor` 只认识 `IPlayerInput`，迁移到新 Input System 时只换 `LegacyPlayerInput`。
- **Bootstrap 负责 new 对象和注入**：`new GameClock`、`new WaveScheduler`、`new BattleSession`、`new KillAuraSystem`、`new OffscreenRecycler`，再把 `CameraViewport` / `LegacyPlayerInput` 注入 Gameplay。

### 5.3 运行时数据流

```
DataDocs/level01_enemy_spawn.csv
        +  Data/BattleConfig.asset
                    │
                    ▼
        Bootstrap.BattleBootstrap（组合根）
          ├─ Data.WaveTable.Parse / ValidateForRun
          ├─ Core.GameClock / EventBus / ObjectPool
          ├─ Platform.LegacyPlayerInput
          └─ Gameplay.BattleSession / WaveScheduler / EnemySpawner /
             KillAuraSystem / OffscreenRecycler
                    │
                    ├─ 切波 / 刷怪 / 追击（Gameplay）
                    ├─ 击杀、清场（Gameplay）
                    └─ EventBus（Core）
                              │
                              ▼
                 Presentation.BattleHud / AuraView / PlayerSpriteView
```

场景内没有手摆的敌人；蝙蝠由 `EnemySpawner` 从 `EnemyBat.prefab` 实例化并池化。
所有 Sprite 使用 `SpriteUnlit.mat`（URP 2D Unlit），不依赖 2D 光照；光环贴图是运行时生成的径向渐变，不新增美术资源。

> 这次重构**没有**引入武器、经验、秘法牌、空间哈希等尚未实现的功能；只把现有“移动 + 波次 + 击杀光环 + 胜利”这条链路按层拆开。
> 敌人 AI 仍然是每个 `EnemyBat.Update` 自己跑；同屏约 300 只时没问题，后续要做 M5/M11 的性能优化再引入集中调度/空间哈希。

## 七、已知限制

1. **中文字体**：项目还没有 TMP 中文字体资源，HUD 用 `Font.CreateDynamicFontFromOSFont` 取系统中文字体
   （优先 Microsoft YaHei UI / Microsoft YaHei / SimHei）。换机器或换字体时改 `HudFont.cs` 即可。
2. **草地重复**：只有一张 32×32 的 `tile_grass.png`，平铺后 1 单位周期比较明显；后续有更大图块或 Tilemap 再替换。
3. **蝙蝠只有一种行为**：直线追踪，没有攻击/受击/碰撞分离；本场景只验证波次与光环。
4. **时长固定 5 分钟**：没有倍速/跳过；验证胜利要等真实 300 秒，或临时改 `Assets/Data/BattleConfig.asset` 的 `runDurationSeconds`（需同步改 CSV 最后一波时间）。
