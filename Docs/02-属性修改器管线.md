# 02 · 属性修改器管线（Stat Pipeline）

> 对应 `JobHunt/Unity-技术实现清单.md` 的 **M2 属性管线**。
> 实现位置：`Assets/Scripts/Core/Stats/`（Core 层）+ `Assets/Scripts/Gameplay/PlayerStats.cs`。
> 这个系统只负责“数值怎么从 base 算成最终值”；武器、被动、秘法牌、强化等系统只负责“在什么时候加/减哪条修改器”。

---

## 一、为什么不能直接 `stat += 0.1f`

直接改数值有三个问题：

1. **无法正确移除**：多个来源叠加后，移除其中一个不知道要减多少；
2. **顺序不可控**：`+10%` 和 `×1.2` 的先后会得到不同结果；
3. **重复计算**：同一个卡牌/被动被注册两次，数值会漂移。

本管线把“数值来源”统一成 **修改器（StatModifier）**：

- 每个属性保存 **BaseValue + 修改器列表**；
- 任何系统都只能 `AddModifier / RemoveModifier`；
- 每次重算都 **从 BaseValue 重新算**，不做增量累加；
- 用 **Id 去重**、**SourceId 分组移除**、**脏标记合并同帧多次修改**。

## 二、文件与层次

```
Assets/Scripts/
  Core/Stats/
    StatType.cs           属性枚举 + 单位约定
    StatModifierType.cs   FlatAdd / PercentAdd / PercentMul
    StatModifier.cs       一条不可变修改器（SourceId / Id / Type / Value）
    Stat.cs               单条属性：BaseValue + 修改器 + 脏标记重算
    StatBlock.cs          一组属性的容器
  Gameplay/
    PlayerStats.cs        玩家属性表：从 BattleConfig 建基础值
```

依赖方向：`Core.Stats` 只依赖 .NET；`Gameplay.PlayerStats` 依赖 `Data` + `Core`；Presentation 可以读 `Stat`，但不能写。

## 三、计算规则

最终值固定按下面顺序计算：

```
Value = clamp(
    (BaseValue + Σ FlatAdd)
    × (1 + Σ PercentAdd)
    × Π (1 + PercentMul),
    MinValue
)
```

- `FlatAdd`：直接加绝对值；
- `PercentAdd`：所有百分比先求和，再一次性乘；
- `PercentMul`：每条单独乘 `(1 + Value)`，多条连乘；
- 修改器的注册顺序不影响结果；
- 每次重算从 `BaseValue` 开始，移除后能精确回到 base。

例子：base 100、Flat +20、PercentAdd +50%、PercentMul +50%

```
(100 + 20) × (1 + 0.5) × (1 + 0.5) = 270
```

## 四、API 与规则

### 4.1 加修改器

```csharp
Stat might = playerStats.Get(StatType.Might);

// 单条来源：Id 省略时自动等于 SourceId
might.AddModifier(StatModifier.PercentAdd("passive.hollowHeart", 0.1f));

// 一个来源给同一条属性加多条：必须给不同的 Id
might.AddModifier(StatModifier.Flat(
    sourceId: "passive.hollowHeart",
    value: 5f,
    id: "passive.hollowHeart.flat"));
might.AddModifier(StatModifier.PercentAdd(
    sourceId: "passive.hollowHeart",
    value: 0.1f,
    id: "passive.hollowHeart.percent"));
```

规则：

- **同一个 Stat 内，`Id` 唯一**；重复 `AddModifier` 相同 `Id` 会**替换**旧修改器，不会叠成两条。
- `SourceId` 用于“整组移除”和调试；建议用稳定的前缀：
  `powerup.*`、`passive.*`、`weapon.*`、`arcana.*`、`enemy.*`、`debug.*`。
- **不要**每帧 `AddModifier` 来刷新数值；动态数值用 `SetModifierValue`（见震荡）。

### 4.2 移除

```csharp
// 精确移除一条
might.RemoveModifier("passive.hollowHeart.flat");

// 移除某个来源的全部修改器（推荐在失去道具/一局结束时用）
might.RemoveAllModifiersFromSource("passive.hollowHeart");

// 一局结束/对象复用
might.ClearModifiers();
```

### 4.3 动态数值 / 震荡

`SetModifierValue` 只改某条已存在修改器的“当前系数”，然后标脏；下一次读 `Value` 时从 base 重算。

```csharp
Stat area = playerStats.Get(StatType.Area);

// 开局注册一次，Value 先用 0
area.AddModifier(StatModifier.PercentAdd("arcana.V", 0f, "arcana.V"));

// 每帧只注入当前相位，不要做 area.Value *= 系数
float phase = Mathf.Sin(Time.time * 2f) * 0.5f; // -50% ~ +50%
area.SetModifierValue("arcana.V", phase);

float current = area.Value; // 从 base 重算，相位回到 0 时精确回到 base
```

这是 M2 里“震荡类卡牌不能每帧乘算”要求的落点：**相位是输入，重算从 base 开始**，所以不会漂移。

### 4.4 脏标记

- `AddModifier / RemoveModifier / RemoveAllModifiersFromSource / SetModifierValue / SetBaseValue` 只标脏；
- 下一次读取 `Value` 才真正重算，同一帧多次修改会合并成一次；
- `RecalculationCount` 可用于调试/测试确认没有重复重算；
- `Changed` 事件在重算后值确实变化时触发；UI 可以订阅它，但 **不要**在回调里再读 base 或写 Value。

### 4.5 下限

`Stat` 构造时传入 `minValue`，最终值会被钳制。比如冷却时间 `min = 0.1`，移动速度 `min = 0`，发射数量 `min = 1`。

## 五、当前测试场景的接入

`Gameplay.PlayerStats` 根据 `BattleConfig` 建出一张完整属性表：

| 属性 | Base | 单位/说明 | 当前是否使用 |
| --- | --- | --- | --- |
| Might | 1.0 | 倍率 | 预留 |
| Armor | 0 | 数值 | 预留 |
| MaxHealth | 100 | 数值 | 预留 |
| Recovery | 0 | 数值 | 预留 |
| Cooldown | 1.0 | 倍率，越小越快 | 预留 |
| Area | 1.0 | 倍率 | 预留（正式武器范围） |
| ProjectileSpeed | 1.0 | 倍率 | 预留 |
| Duration | 1.0 | 倍率 | 预留 |
| Amount | 1 | 数量 | 预留 |
| **MoveSpeed** | `BattleConfig.PlayerMoveSpeed`（4.2） | 单位/秒 | **PlayerMotor** |
| Magnet | 1.0 | 倍率 | 预留 |
| Luck | 1.0 | 倍率 | 预留 |
| Growth | 1.0 | 倍率 | 预留 |
| Greed | 1.0 | 倍率 | 预留 |
| Curse | 1.0 | 倍率 | 预留 |
| Revival | 0 | 次数 | 预留 |
| **AuraRadius** | `BattleConfig.AuraRadius`（2） | 世界单位 | **KillAuraSystem + AuraView** |

接入点：

- `BattleBootstrap.Start` 里 `new PlayerStats(config)`；
- `PlayerMotor.Initialize(input, stats.MoveSpeed)`，移动时只读 `MoveSpeed.Value`；
- `KillAuraSystem` 和 `AuraView` 共用 `stats.AuraRadius`，所以判定圆和视觉圆始终同步；
- `BattleBootstrap.Stats` 暴露属性表，后续系统由组合根从这里拿引用。

基础值保持不变，所以接入管线后当前玩法数值与之前一致。

## 六、后续新增系统怎么接

### 6.1 被动道具

```csharp
public sealed class PassiveHollowHeart
{
    private readonly Stat _maxHealth;

    public PassiveHollowHeart(PlayerStats stats)
    {
        _maxHealth = stats.Get(StatType.MaxHealth);
    }

    public void OnAcquire()
    {
        _maxHealth.AddModifier(StatModifier.Flat("passive.hollowHeart", 20f));
    }

    public void OnRemove()
    {
        _maxHealth.RemoveAllModifiersFromSource("passive.hollowHeart");
    }
}
```

- 拿到道具：注册；失去/一局结束：按 SourceId 移除。
- 有多个效果时用不同的 `Id`（`passive.hollowHeart.flat` / `.percent`），否则同 Id 会互相替换。

### 6.2 武器

```csharp
public sealed class WeaponRuntime
{
    private readonly Stat _might;
    private readonly Stat _cooldown;
    private readonly Stat _area;
    private readonly Stat _amount;

    public WeaponRuntime(PlayerStats stats)
    {
        _might = stats.Get(StatType.Might);
        _cooldown = stats.Get(StatType.Cooldown);
        _area = stats.Get(StatType.Area);
        _amount = stats.Get(StatType.Amount);
    }

    public void Fire()
    {
        float damage = baseDamage * _might.Value;
        float cooldown = baseCooldown * _cooldown.Value;
        float radius = baseRadius * _area.Value;
        int projectiles = Mathf.RoundToInt(_amount.Value);
        // ...
    }
}
```

- 武器不要在构造时缓存 `might.Value`，每次使用/开火时读，或订阅 `Changed`；
- 冷却计时器用 `Cooldown.Value` 计算下一次开火时间；
- 武器自己不要改 `Might`，只读。

### 6.3 武器进化

- 进化时不要重建武器对象（避免引用失效）；
- 先 `RemoveAllModifiersFromSource("weapon.oldId")` 清理旧武器的修改器；
- 替换武器数据/行为，再用 `weapon.evolvedId` 重新注册；
- 保留同一 `WeaponRuntime` 实例，UI/冷却计时器不用重绑。

### 6.4 秘法牌

| 卡牌类型 | 接法 |
| --- | --- |
| 常驻属性（V/XVIII/XX） | 开局/拿卡时 `AddModifier`，SourceId = `arcana.V`；震荡用 `SetModifierValue` 每帧注入相位 |
| 事件触发（II/VI/XVI） | 订阅 `Core.EventBus` 的事件，在回调里通过 EventBus 或伤害系统结算；**不要**在回调里直接改 Stat.Value |
| 状态标记（XI 弹射） | 在武器/投射物状态上打标记，读取 `Stat` 的当前值决定弹射次数 |
| 流程介入（IV 复活） | 走流程/事件（例如 `BattleSession` 的复活钩子），不放进属性管线 |

拿到卡：注册；一局结束/换卡：按 `arcana.<id>` 移除。建议每张卡只用一个 SourceId，内部多个效果用不同 Id。

### 6.5 局外强化（PowerUp）

- 开局时根据已购买等级注册修改器，SourceId = `powerup.might` 等；
- 这些修改器在本局内是常驻的，不随升级移除；
- 如果以后支持“重置强化”，按 SourceId 整组移除。

### 6.6 敌人 / 精英

`StatBlock` 不只给玩家用。敌人可以有自己的一张表：

```csharp
var enemyStats = new StatBlock(new[]
{
    new Stat(StatType.MaxHealth, 20f, 1f),
    new Stat(StatType.MoveSpeed, 2.5f, 0f),
    new Stat(StatType.Might, 1f, 0f)
});

enemyStats.Get(StatType.MaxHealth)
    .AddModifier(StatModifier.PercentAdd("enemy.elite", 0.5f));
```

- 玩家和敌人各持有一张表，互不污染；
- 伤害结算读 `attacker.Might` 和 `target.Armor`，不要让某个脚本直接改血量常量。

### 6.7 UI

```csharp
Stat might = playerStats.Get(StatType.Might);
might.Changed += OnMightChanged; // OnDisable/OnDestroy 记得退订
text.text = $"{might.Value * 100f:0}%";
```

- UI 只读 `Value`；需要实时刷新就订阅 `Changed`；
- 不要在 UI 里做倍率计算（显示时把 1.0 格式化成 100% 即可）；
- 如果 UI 需要“基础值 + 加成来源明细”，读 `Modifiers`（只读视图），不要修改。

### 6.8 存档 / 一局重置

- **不要**序列化 `Stat` / `StatBlock`（它们是运行时对象，含事件和修改器列表）；
- 存档存 **基础值 + 已获得来源列表**（道具/卡牌/强化等级）；
- 读档时重建 `PlayerStats`，再按来源重新 `AddModifier`；
- 一局结束调用 `ClearModifiers()` 或重建 `PlayerStats`，避免跨局污染。

### 6.9 新增一条属性

1. 在 `StatType` 加枚举；
2. 在 `PlayerStats` 的构造里加 `new Stat(type, baseValue, minValue)`；
3. 使用它的系统注入 `Stat` 引用，按上面的规则加修改器；
4. 如果它需要配置表，把 base 值放进 `BattleConfig`/后续的 Data 表；
5. 不需要改 `Stat`/`StatModifier` 的代码。

## 七、测试

`Assets/Tests/EditMode/StatPipelineTests.cs`（编辑模式，不依赖场景）：

- Flat → PercentAdd → PercentMul 固定顺序；
- 同 Id 替换而不是叠加；
- 按 Id / SourceId 移除；
- 从 base 重算，不残留；
- 震荡 `SetModifierValue` 回到 0 相位精确回到 base；
- 脏标记：连续读只重算一次，多次修改合并；
- SetBaseValue、下限钳制、PercentMul 连乘；
- `Changed` 事件只在值变化时触发；
- `StatBlock.Get/TryGet`、非法修改器参数；
- `PlayerMotor` 的移动速度确实来自 `MoveSpeed` Stat，加 +50% 后下一帧位置立即变化。

当前共 **13 个** EditMode 测试，全部通过。

运行：

```
Unity.exe -batchmode -nographics -projectPath <项目> `
  -runTests -testPlatform EditMode `
  -testResults Logs/editmode-results.xml
```
